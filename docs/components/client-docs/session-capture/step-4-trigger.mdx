A recording trigger watches for steps in order on the same tab, then uploads the replay it buffered and keeps recording for a while. Build one in a rule's **Triggers** tab ([Step 6](#step-6-change-collection-remotely-with-data-collection-rules) shows how to open a rule):

1. Click **Add recording trigger** and enter a **Trigger name**, such as `Checkout failed`. Sessions it records show that name.
2. Add up to five steps with **Add step**. Each step is an **Event**:
   - **Click** or **Hover** with a CSS selector ([next section](#name-the-elements-a-trigger-can-match));
   - **Navigation** with a route pattern such as `/orders/{id}`, where `{id}` matches one path segment;
   - **Log** with a log message, which **Exactly matches** or **Contains** the line.
3. Set **Within seconds of previous step** where the steps must follow each other quickly, then **Replay lookback (seconds)**, **Continue recording (seconds)**, **Cooldown (seconds)** and **Captures per session**.
4. Save the rule.

Below the recording triggers, **Capture when a log line appears** starts a capture when a line repeats, for example `payment failed` 3 times within 60 seconds, and streams for a number of minutes, with or without replay.
