# Flush & Lifecycle

The 2.x browser SDK sends streamed telemetry through OpenTelemetry batch processors. `exportDelayMs` sets the usual delay, defaulting to 1000 ms. Performance metrics upload on their own interval, five minutes by default, and when the page is hidden. Buffered telemetry stays on the device until a trigger or capture asks for it.

## Flush queued telemetry

```javascript
import { captureException, flush } from "@tracewayapp/frontend";

try {
  await submitOrder();
} catch (error) {
  captureException(error);
  await flush();
}
```

`flush()` sends queued logs, spans and replay uploads and the pending performance metrics, and checkpoints the telemetry buffer. It does not release buffered telemetry or force an in-progress replay segment to complete, and it does not end the session. A captured exception normally fires the built-in error trigger, which selects the lookback and replay clip before this flush.

`flush(timeoutMs)` bounds how long the caller waits; it does not cancel outstanding requests. Its completion is not a guarantee that every record reached the server: exporters can reject or retry data. Before `init()`, `flush()` resolves at once.

## Navigation and connectivity

The SDK handles `visibilitychange` and `pagehide`. It closes a streaming replay segment, uploads the pending performance metrics, sends what is queued while the page can still send it, and checkpoints telemetry for the next page of the same session. Browser termination, blocked storage, storage quotas, and the browser's keepalive body limit can still cause data loss.

With `buffer.persist: true`, the default, failed OTLP batches wait in IndexedDB and retry with backoff while the page remains open, on connectivity recovery, and on later pages. Replay uploads have a separate bounded retry queue in memory. See the [buffer reference](/learn/remote-config/reference#buffer) for retention limits.

For an application-controlled redirect, await `flush()` before changing location:

```javascript
await flush(2000);
window.location.href = "/next-page";
```

## Shutdown

```javascript
import { shutdown } from "@tracewayapp/frontend";

await shutdown();
```

Shutdown reports the session's end and closes its current replay segment, flushes queued telemetry and metrics, stops polling and retry timers, and removes instrumentation. A later `init()` creates a fresh client; await `shutdown()` before calling it. Without a shutdown, a second `init()` is ignored. A new client in the same tab continues the session when it starts within the session's inactivity timeout.

Initialize once in a single-page application. In a server-rendered application the SDK only does work in the browser: on the server `init()` starts nothing and captures are ignored. The framework wrappers handle their respective mount lifecycles; follow each guide on where to call them (the Svelte setup, for example, must also run during server rendering).

## Timing options

```javascript
init(connectionString, { exportDelayMs: 500 });
```

SDK 1.x's `debounceMs` and `retryDelayMs` options were removed in 2.x. The exporter delay is separate from buffering, capture duration, the metric upload interval (`collection.metrics.flushSeconds`), and the OpAMP polling interval.
