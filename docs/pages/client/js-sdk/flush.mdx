The 2.x browser SDK sends streamed telemetry through OpenTelemetry batch processors. `exportDelayMs` sets the usual delay, defaulting to 1000 ms. Buffered telemetry stays on the device until a trigger or capture asks for it.

## Flush queued telemetry

```javascript
import { captureException, flush } from "@tracewayapp/frontend";

try {
  await submitOrder();
} catch (error) {
  captureException(error);
  await flush();
}
```

`flush()` sends queued logs, spans and replay uploads, and checkpoints the telemetry buffer. It does not upload every buffered record or force an in-progress replay segment to complete. A captured exception normally fires the built-in error trigger, which selects the lookback and replay clip before this flush.

`flush(timeoutMs)` bounds how long the caller waits; it does not cancel outstanding requests. Successful completion is not a guarantee that every record reached the server: exporters can reject or retry data.

## Navigation and connectivity

The SDK handles `visibilitychange` and `pagehide`. It closes a streaming replay segment, queues uploads while the page can still send them, and checkpoints telemetry for the next page of the same session. Browser termination, blocked storage, storage quotas, and the browser's keepalive body limit can still cause data loss.

With `buffer.persist: true`, failed OTLP batches wait in IndexedDB and retry with backoff while the page remains open, on connectivity recovery, and on later pages. Replay uploads have a separate bounded retry queue in memory. See the [buffer reference](/learn/remote-config/reference#buffer) for retention limits.

For an application-controlled redirect, await `flush()` before changing location:

```javascript
await flush(2000);
window.location.href = "/next-page";
```

## Shutdown

```javascript
import { shutdown } from "@tracewayapp/frontend";

await shutdown();
```

Shutdown closes the session's current replay segment, flushes queued telemetry, stops polling and retry timers, and removes instrumentation. Call `init()` again to create a fresh client.

Initialize once in a single-page application. For server-rendered applications, initialize on the browser side only. The framework wrappers handle their respective mount lifecycles.

## Timing options

```javascript
init(connectionString, { exportDelayMs: 500 });
```

SDK 1.x's `debounceMs` and `retryDelayMs` options were removed in 2.x. The exporter delay is separate from buffering, capture duration, and the OpAMP polling interval.
