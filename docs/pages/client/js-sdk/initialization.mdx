# Initialization

Initialize the Traceway SDK once at application startup, before capturing any events.

## Basic Initialization

```javascript
import { init } from "@tracewayapp/frontend";

init({ token: import.meta.env.VITE_TRACEWAY_TOKEN });
```

`token` is the project token from the project's **Connection** page. The SDK sends to Traceway Cloud (`https://cloud.tracewayapp.com`); for a self-hosted server, add its address as `baseUrl`. [Token and server](/client/js-sdk#token-and-server) lists the environment variables of each build tool.

`init()` runs once per page: a second call is ignored, because the instrumentations patch browser globals once. To initialize again with different options, shut the first client down and wait for it:

```javascript
import { init, shutdown } from "@tracewayapp/frontend";

await shutdown();
init({ token: import.meta.env.VITE_TRACEWAY_TOKEN, environment: "staging" });
```

`init()` never throws. Given options it cannot use (no token, as in a preview build without its environment variable, or `telemetry.url: "not a url"`), it logs one `console.warn` such as `Traceway: init() failed and the SDK is off: Error: init() needs a token, as in init({ token: "YOUR_TOKEN" }), and got undefined: is the environment variable set in this build? …`, and the SDK stays off: every other function does nothing until a later `init()` succeeds. Where there is no `window` (server-side rendering), `init()` does nothing.

## With Options

Every option goes in the same object as the token:

```javascript
import { init } from "@tracewayapp/frontend";

init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  baseUrl: import.meta.env.VITE_TRACEWAY_URL, // only for a self-hosted server
  debug: true,
  version: "1.2.3",
  exportDelayMs: 2000,
  serviceName: "shop-web",
  environment: "production",
});
```

keep it on the device, but never turn on what `init()` turned off. A ceiling that is left on does not start a signal by itself: the events of
resource timing, long tasks and route timing are `off` in the default collection settings until `collection`, a rule, a trigger or a capture
turns them on. The `DEFAULT_IGNORE_PATTERNS` export contains the built-in `ignoreErrors` list.

The 1.x options `debounceMs`, `retryDelayMs`, `eventsWindowMs` and `eventsMaxCount` no longer exist. `exportDelayMs` replaces `debounceMs`, the SDK manages retries itself, and retention is set with `collection.buffer.maxAgeSeconds` and `collection.buffer.maxBytes` or a rule. See [Upgrading](/client/js-sdk/migration).

## Auto-Capture Behavior

`init()` installs the global handlers for you. Uncaught errors (the window's `error` event) and unhandled promise rejections (its `unhandledrejection` event) are captured automatically in every JS SDK: plain, React, Vue, Svelte, and jQuery alike. The SDK listens with `addEventListener`, so a `window.onerror` your app assigns does not replace it, and the page's own handlers still receive every error unchanged.

```javascript
import { init } from "@tracewayapp/frontend";

init({ token: import.meta.env.VITE_TRACEWAY_TOKEN });

// Nothing else to wire up. This is already reported:
setTimeout(() => {
  throw new Error("Boom");
});
```

> **Do not add your own `window.addEventListener("error")` or `"unhandledrejection"` listener that calls `captureException`.** The SDK's handlers are already attached. A second capture of the same error within a second is suppressed as a duplicate, so the listener adds nothing, and an error it reports later or in a different form is counted twice.

The framework packages add render-time capture on top of this: React's `TracewayProvider` doubles as an error boundary, and the Vue plugin installs `app.config.errorHandler`. Manual `captureException` calls are only needed where the error never becomes uncaught, such as inside a `try`/`catch` or an event handler that swallows it.

Exceptions, messages, log lines and actions carry the screen the page showed (`app.screen.name`, `app.screen.route`, `app.screen.previous`, `app.screen.duration_ms`, `viewport`); see [Screens and navigation](/client/js-sdk#screens-and-navigation).

## Error Filtering

By default, the SDK ignores common non-actionable errors: **4xx HTTP errors**, **network errors**, and **timeouts**. These are typically expected application behavior (e.g., form validation returning 422, auth redirects from 401) rather than bugs that need tracking.

### Default Behavior

The following patterns are ignored out of the box:

- `"Failed to fetch"` (Chrome), `"Load failed"` (Safari), `"NetworkError when attempting to fetch resource"` (Firefox), `"Network Error"` (Axios), `"Network request failed"` (React Native style)
- `"The operation was aborted"` (AbortController), any message matching `/timeout/i`
- Axios 4xx errors matching `/status code 4\d{2}/`
- jQuery/custom 4xx errors matching `/failed: 4\d{2}/`

### Capture All Errors

To opt out of default filtering and capture everything:

```javascript
init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  ignoreErrors: [],
});
```

### Custom Patterns

Pass your own patterns to replace the defaults. Strings match via `includes()`, RegExps match via `.test()`. Patterns are tested against the `Type: message` line of the error, never its stack frames:

```javascript
init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  ignoreErrors: ["ResizeObserver loop", /status code 5\d{2}/],
});
```

### Extending Default Patterns

Import `DEFAULT_IGNORE_PATTERNS` to add your own patterns on top of the defaults:

```javascript
import { init, DEFAULT_IGNORE_PATTERNS } from "@tracewayapp/frontend";

init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  ignoreErrors: [...DEFAULT_IGNORE_PATTERNS, "ResizeObserver loop"],
});
```

### beforeCapture Callback

For fine-grained control, use the `beforeCapture` callback. It receives a `TracewayCapturedError` and returns `false` to drop the event:

| Field        | Value                                                                                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `error`      | What was thrown or passed to `captureException`; `undefined` for a message                                                                                                                                          |
| `type`       | The error's type, e.g. `TypeError`; `undefined` for a message                                                                                                                                                       |
| `message`    | The error's message, or the message text                                                                                                                                                                            |
| `isMessage`  | `true` for `captureMessage`                                                                                                                                                                                         |
| `stack`      | The stack trace; `undefined` for a message                                                                                                                                                                          |
| `attributes` | A copy of every attribute the event will carry: the ones passed with the call, the global ones (`setAttribute`), the page's (`url`, `path`, `userAgent` and the rest), the screen keys and the `exception.*` fields |

```javascript
import { init } from "@tracewayapp/frontend";

class PaymentDeclined extends Error {}

init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  ignoreErrors: [],
  beforeCapture: (captured) => {
    // An error the app expects
    if (captured.error instanceof PaymentDeclined) return false;

    // Suppress 401 errors based on attributes (e.g., from jQuery AJAX capture)
    if (captured.attributes?.status === "401") return false;

    // Suppress errors from third-party scripts
    if (captured.stack?.includes("third-party.js")) return false;

    return true;
  },
});
```

`beforeCapture` is checked **after** `ignoreErrors`. If a pattern already suppresses the error, the callback is not called. If the callback throws, the error is captured normally (safe default), and `debug: true` logs `Traceway: beforeCapture threw`.

Both filters also see `captureMessage` calls. A message is matched by its text. `TracewayCapturedError` was called `CapturedException` in 2.0; that name stays as a deprecated alias.

## Debug Mode

`debug: true` logs with the page's own `console.warn`, so Traceway never records these lines:

- the start: `Traceway: started (https://cloud.tracewayapp.com/api/otel/v1/logs), session …`;
- remote config applied (`Traceway: remote config applied (…)`), rejected, or unavailable;
- every exception or message the SDK drops, and why: `ignoreErrors`, `beforeCapture`, `errorLimits`, or the session upload budget (`collectionLimits`);
- a repeated `init()`, the Vue plugin's caught errors, and SDK failures it contained.

```javascript
init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  debug: import.meta.env.DEV,
});
```

A setup mistake, such as a missing token or a deprecated connection string, is logged once even without `debug`. To verify ingestion, watch `POST /api/otel/v1/logs` and `POST /api/otel/v1/traces` in the Network tab, or call `await flush()` and open the Issues page. Replay uses `/api/recordings`.

## Custom Attributes (Global Scope)

The SDK auto-collects browser context (`url`, `userAgent`, `viewport`, etc.) on every session and exception. To attach app-level identifiers (`user.id`, `tenant`, feature flags), call the imperative scope API once and they ride along every subsequent event:

```javascript
import {
  setAttribute,
  setAttributes,
  removeAttribute,
  clearAttributes,
} from "@tracewayapp/frontend";

setAttribute("user.id", "u_42");
setAttributes({ tenant: "acme", plan: "pro" });

// On logout / tenant switch:
clearAttributes();
```

Layering on each event: **defaults < global scope < per-call**. `captureException(err, { … })` still wins over global keys for the specific exception.

When sessions are enabled, calling `setAttribute*` mid-session also pushes a refresh upsert so the live session row picks up the new attributes immediately rather than waiting for close. See [Sessions](/learn/sessions) for the full attribute model.

## Multiple Environments

Give each environment its own project, and so its own token, through the build's environment variables:

```bash
# .env.production
VITE_TRACEWAY_TOKEN=YOUR_PRODUCTION_TOKEN

# .env.development
VITE_TRACEWAY_TOKEN=YOUR_DEVELOPMENT_TOKEN
```

```javascript
init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  environment: import.meta.env.MODE,
});
```

## Setups

The SDK runs in one of three ways. The first needs nothing beyond the token.

### Everything on Traceway

```javascript
import { init } from "@tracewayapp/frontend";

init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  serviceName: "shop-web",
  environment: "production",
});
```

The browser polls Traceway for its collection settings, sends logs, request spans and metrics to Traceway's OTLP endpoints, and uploads replay to the same server. What browsers collect is changed on the project's **Data Collection** page; see [Remote SDK Config](/learn/remote-config/setup).

### Send telemetry to another OpenTelemetry provider

The `telemetry` option sends logs, traces and metrics to any OTLP/HTTP endpoint, such as an OpenTelemetry Collector in front of a Grafana stack. With a `token`, errors, replay, captures and remote config stay on Traceway:

```javascript
import { init } from "@tracewayapp/frontend";

init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  serviceName: "shop-web",
  telemetry: {
    url: "https://collector.example.com/otlp",
    headers: { "X-Ingest-Key": "browser-safe-key" },
    // Optional overrides are complete signal URLs; no path is appended.
    metrics: { url: "https://metrics.example.com/v1/metrics" },
  },
  collection: {
    signals: { console: { mode: "stream" }, network: { mode: "stream" } },
    metrics: { flushSeconds: 30 },
  },
});
```

The collector hosts are examples: use your own. A shared `telemetry.url` gets `/v1/logs`, `/v1/traces` and `/v1/metrics` appended. Each signal (`logs`, `traces`, `metrics`) can override it with `{ url, headers }`. Without a shared `url`, the signals you do not list keep their Traceway destination, so `telemetry: { metrics: { url } }` moves the metrics only. URLs must use HTTP(S), without embedded credentials, a query, or a fragment. Signal headers override the shared `telemetry.headers`; Traceway's token is never added to external requests.

When logs are redirected, exception events, `captureMessage` issues, and SDK control and session events still go to Traceway, and only there. Ordinary console, custom and performance logs go to the logs receiver; request spans and metrics use their own destinations. Remote config and rrweb recordings keep using the Traceway server (`baseUrl`). External breadcrumbs are not copied into Traceway's session timeline; both destinations carry `session.id` for correlation.

Live exports, restored buffers, and retries use the configured signal destinations and credentials. Persistent telemetry queues and pending metric batches are kept per destination. A custom `logExporter` or `spanExporter` replaces the corresponding live exporter; Traceway's issue and session routing still applies, and persisted records use the configured HTTP destinations.

The receiver must accept OTLP/HTTP JSON and allow your application's origin, POST, and the configured headers through CORS. Use browser-safe ingestion credentials or your own ingestion proxy; keep backend credentials on the collector. Metrics are delta sums and exponential histograms, so configure the downstream pipeline to accept or convert those types.

### Standalone, without a Traceway server

Leave out the `token` and give a `telemetry` destination:

```javascript
import { init, metric, count } from "@tracewayapp/frontend";

init({
  serviceName: "shop-web",
  telemetry: { url: "https://collector.example.com/otlp" },
  collection: {
    signals: {
      console: { mode: "stream", minSeverity: "warn" },
      network: { mode: "stream", sampleRate: 0.25 },
      custom: { mode: "stream" },
    },
    metrics: { flushSeconds: 30 },
    triggers: [{ id: "default-exception", enabled: false }],
  },
});

metric("checkout.duration", 840, { plan: "pro" });
count("checkout.completed");
```

No Traceway server, account, or token is required. `telemetry` must have a shared `url` or all three signal endpoints. Standalone mode turns off remote config, session events, and session replay, whatever those options say. A local session ID still supports sampling and telemetry correlation. Exceptions are ordinary OTLP log records, with the event name `exception`, sent to your collector. The SDK keeps its error filters and collection defaults; set `ignoreErrors: []` to remove the built-in error filters.

These setups apply to `@tracewayapp/frontend` and its React, Vue, Svelte, and jQuery wrappers, which take the same options: the wrappers take `telemetry` with their other options, and leave out `token` to run standalone.

## Local collection settings

`collection` is a partial settings document (the `CollectionSettings` type), with the same schema a [Data Collection rule](/learn/remote-config/reference#the-settings-document) uses. Each signal is in one of three modes: `stream` sends it right away, `buffer` keeps it on the device until a trigger or a capture uploads it, and `off` drops it. Fields you omit keep the SDK defaults:

| Field                         | Default                                                                                                                                                                                   | Meaning                                                                                                                                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `enabled`                     | `true`                                                                                                                                                                                    | `false` stops collection altogether                                                                                                                                                              |
| `signals.<name>.mode`         | `stream` for `errors` and `messages`; `buffer` for `network`, `console`, `navigation`, `userActions`, `custom` and `webVitals`; `off` for `resourceTiming`, `longTasks` and `routeTiming` | `off`, `buffer` or `stream`                                                                                                                                                                      |
| `signals.<name>.sampleRate`   | `1`                                                                                                                                                                                       | Share of records kept, from 0 to 1                                                                                                                                                               |
| `signals.console.minSeverity` | `"info"`                                                                                                                                                                                  | Console records below it are dropped: `trace`, `debug`, `info`, `warn`, `error` or `fatal`                                                                                                       |
| `sessions.enabled`            | `true`                                                                                                                                                                                    | Report session start and end                                                                                                                                                                     |
| `sessions.baselineSampleRate` | `0`                                                                                                                                                                                       | Same as the `baselineSampleRate` option                                                                                                                                                          |
| `replay.mode`                 | `buffer`                                                                                                                                                                                  | `off`, `buffer` or `stream`                                                                                                                                                                      |
| `replay.sessionSampleRate`    | `1`                                                                                                                                                                                       | Share of sessions whose replay may stream; the rest keep it buffered                                                                                                                             |
| `replay.maskAllInputs`        | `true`                                                                                                                                                                                    | Mask the values of form inputs in the recording                                                                                                                                                  |
| `replay.images`               | `wifi`                                                                                                                                                                                    | What the replay shows of pictures: `off` (empty boxes), `wifi` (URL references) or `always` (URL references plus small copies). See [Replay images](/client/js-sdk/session-replay#replay-images) |
| `metrics.enabled`             | `true`                                                                                                                                                                                    | Aggregate and upload [performance metrics](/learn/client-metrics)                                                                                                                                |
| `metrics.sampleRate`          | `1`                                                                                                                                                                                       | Share of sessions that record metrics                                                                                                                                                            |
| `metrics.flushSeconds`        | `300`                                                                                                                                                                                     | Metric upload interval, held between 30 and 3600 seconds                                                                                                                                         |
| `buffer.maxBytes`             | `2097152` (2 MiB)                                                                                                                                                                         | Maximum size of the buffered telemetry; at most 64 MiB                                                                                                                                           |
| `buffer.maxAgeSeconds`        | `600`                                                                                                                                                                                     | Maximum age of buffered telemetry and replay; at most 24 hours                                                                                                                                   |
| `buffer.replayMaxBytes`       | `8388608` (8 MiB)                                                                                                                                                                         | Maximum size of the buffered replay segments; at most 64 MiB                                                                                                                                     |
| `buffer.persist`              | `true`                                                                                                                                                                                    | Keep buffered telemetry and failed exports in IndexedDB across page loads                                                                                                                        |
| `triggers`                    | the built-in `default-exception` trigger                                                                                                                                                  | On-device triggers, merged by `id`                                                                                                                                                               |

With `recordAllSessions: true` the defaults of `network`, `console`, `navigation`, `userActions`, `custom` and `replay.mode` are `stream`.

Triggers merge by id: an entry with only an `id` and the fields to change patches a trigger that already exists, so `{ id: "default-exception", enabled: false }` stops the automatic upload of breadcrumbs and a replay clip with an error. A new trigger needs `steps` and `actions`; see the [trigger reference](/learn/remote-config/reference#triggers). `exportDelayMs` controls log and span batching, and `metrics.flushSeconds` controls metric uploads. `flush()` sends queued exports and pending metrics, but does not release buffered events; a trigger's `flush` action or a capture releases those.

Settings are applied in this order, each step overriding the one before:

1. The built-in defaults, as `recordAllSessions` and `baselineSampleRate` set them.
2. The local `collection`.
3. The remote settings: the copy cached from an earlier page load, then the live answer from Traceway.
4. The `capture*`, `sessions`, `sessionRecording` and `replayImages` ceilings, lowered further by the limits of the organization's plan when Traceway sends any. Nothing can exceed them; triggers and captures respect them too. `replay.maskAllInputs: true` in the local `collection` is a floor in the same way: no rule unmasks inputs.

To keep Traceway issues and replay with a policy that only a release can change, pass the token with `remoteConfig: false`. No cached remote settings are read and no remote-config request is sent:

```javascript
init({
  token: import.meta.env.VITE_TRACEWAY_TOKEN,
  remoteConfig: false,
  collection: { signals: { custom: { mode: "stream" } } },
});
```

## Servers without remote config

The SDK always sends OTLP. A server without OpAMP (it answers 404, 405 or 501) turns remote config off: telemetry is still sent, and the local settings apply (`collection` and the defaults). A server that cannot be reached keeps the last applied settings while OpAMP retries with backoff, and a rejected token turns remote config off. A self-hosted Traceway server from before OTLP support receives nothing from this SDK: upgrade the server first.

## Production collection policy

Production defaults send session lifecycle metadata and the aggregated [performance metrics](/learn/client-metrics), and keep healthy breadcrumbs, web vital events and replay buffered locally. An accepted exception uploads up to 10 minutes of buffered breadcrumbs and a 30-second replay clip; no full-session replay is uploaded by default. Error clips have a 5-second cooldown and a limit of 20 per session; an error inside the cooldown or past the limit still uploads its breadcrumbs.

Errors are not sampled by default. Duplicate exceptions (same type, message and stack) within 1 second are suppressed, and each running client accepts at most 60 errors in a rolling minute. The next accepted error carries the number suppressed since the previous one as `traceway.error.suppressed_count`. Configure `errorLimits: { maxPerMinute: 60, duplicateWindowMs: 1000 }` to tune these limits: `maxPerMinute` is held between 1 and 1000, `duplicateWindowMs` is at most 60000, and 0 turns duplicate suppression off. The counts reset when the SDK is recreated. Messages are not limited.

For an optional stable sample of healthy-session breadcrumbs and request spans, use `baselineSampleRate: 0.01` (1%). The default is 0. Selection uses the session ID and persists across page reloads within that session. It does not enable replay or override explicitly disabled signals, signal filters, or exporter limits. Performance metrics are uploaded independently of it, so performance diagnosis is not restricted to sessions with errors.
