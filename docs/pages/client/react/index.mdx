# React Quick Start

Integrate Traceway into your React application with the `@tracewayapp/react` package.

import { Callout } from "nextra/components";

<Callout type="info">
  This guide installs the stable 1.x SDK. The 2.x SDK, which adds [remote SDK config](/learn/remote-config) and on-device buffering, is in beta: install `@tracewayapp/react@beta` and follow the [JS SDK reference](/client/js-sdk), where the 1.x pages are under **SDK 1.x (stable)**.
</Callout>

## Installation

```bash
npm install @tracewayapp/react
```

## Setup

Wrap your application with `TracewayProvider`. It also acts as an error boundary: render-time exceptions thrown anywhere in the tree are captured and reported automatically, then re-thrown so your app behaves exactly as it would without Traceway installed. Session recording is on by default; the last ~30s of DOM events ship with every captured exception:

```jsx
import { TracewayProvider } from "@tracewayapp/react";

function App() {
  return (
    <TracewayProvider connectionString="your-token@https://traceway.example.com/api/report">
      <YourApp />
    </TracewayProvider>
  );
}

export default App;
```

> **Custom fallback UI?** If you want to replace a crashed subtree with a fallback view instead of letting the error propagate, wrap the relevant section in `TracewayErrorBoundary`. It's still exported for that purpose, but is no longer required for capture.

Seeing every dev-mode error twice? That is React StrictMode, which double-invokes the provider's constructor and creates two SDK clients. Production is unaffected. See [A note on StrictMode](/client/react/provider#a-note-on-strictmode).

## Capture Errors Manually

Use the `useTraceway` hook in components:

```jsx
import { useTraceway } from "@tracewayapp/react";

function MyComponent() {
  const { captureException } = useTraceway();

  async function handleSubmit() {
    try {
      await submitForm();
    } catch (error) {
      captureException(error);
    }
  }

  return <button onClick={handleSubmit}>Submit</button>;
}
```

## With Options

```jsx
<TracewayProvider
  connectionString="your-token@https://traceway.example.com/api/report"
  options={{
    debug: true,
    version: "1.0.0",
  }}
>
  <YourApp />
</TracewayProvider>
```

## Test Your Integration

```jsx
import { useTraceway } from "@tracewayapp/react";

function TestButton() {
  const { captureException } = useTraceway();

  return (
    <button onClick={() => captureException(new Error("Test error"))}>
      Send Test Error
    </button>
  );
}
```

Click the button and check your Traceway dashboard to verify the error appears.

## Distributed Tracing

The 1.x SDK adds a `traceway-trace-id` header to same-origin `fetch` and `XMLHttpRequest` calls, but Traceway no longer uses it, so 1.x does not link browser errors to backend requests. Exceptions still carry their replay clip. To see a browser request and the backend work it caused in one trace, use the [2.x SDK (beta)](/client/js-sdk/distributed-tracing): it sends the W3C `traceparent` header, which a backend instrumented with OpenTelemetry picks up with no extra middleware. See [Distributed Tracing (SDK 1.x)](/client/js-sdk/v1/distributed-tracing) for what 1.x sends and which old setup code can go.
