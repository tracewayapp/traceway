# TracewayProvider

The `TracewayProvider` component initializes Traceway and provides context to child components.

## Basic Usage

```jsx
import { TracewayProvider } from "@tracewayapp/react";

function App() {
  return (
    <TracewayProvider connectionString="your-token@https://traceway.example.com/api/report">
      <YourApp />
    </TracewayProvider>
  );
}
```

## Props

| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `connectionString` | `string \| StandaloneOptions` | Yes | Your Traceway connection string. An options object with `telemetry` instead runs the SDK against your own OpenTelemetry collector, see [Local configuration without OpAMP](/client/js-sdk/initialization#standalone-without-a-traceway-server) |
| `options` | `TracewayFrontendOptions` | No | Configuration options, passed to `init()` |
| `router` | `object` | No | A React Router data router or a TanStack Router, passed to `trackRouter()` (2.0.1 and later), see [Options](#options) |
| `children` | `ReactNode` | Yes | Child components |

The provider calls `init()` once, in its constructor, so `connectionString`, `options` and `router` are read when it mounts. Changing them later has no effect.

## Options

Since 2.0.1, the optional `router` prop accepts a React Router data router or a TanStack Router instance and names performance metrics by its route templates. See [route setup](/client/react/hooks#usetracewayroute). Pass it directly to `<TracewayProvider router={router}>`.

`options` is the same object `init()` of `@tracewayapp/frontend` takes. The ones used most:

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `version` | `string` | none | Your application version (`service.version`). Groups releases, and remote rules can target it |
| `serviceName` | `string` | the page's host name | `service.name` of this app |
| `environment` | `string` | none | `deployment.environment.name`, e.g. `"production"` |
| `attributes` | `Record<string, string>` | `{}` | Initial global attributes, see [Custom Attributes](#custom-attributes) |
| `debug` | `boolean` | `false` | Log the problems the SDK would otherwise swallow: a rejected project token and a `beforeCapture` that throws. Captured events themselves are not logged |
| `ignoreErrors` | `Array<string \| RegExp>` | `DEFAULT_IGNORE_PATTERNS` | Error patterns to ignore, matched against `Type: message`. Pass `[]` to capture all errors. See [Error Filtering](/client/js-sdk/initialization#error-filtering) |
| `beforeCapture` | `(exception) => boolean` | none | Receives `{ type, message, stack, attributes }`; return `false` to suppress an error. See [Error Filtering](/client/js-sdk/initialization#error-filtering) |
| `sessionRecording` | `boolean` | `true` | Allow rrweb session replay at all |
| `sessionRecordingSegmentDuration` | `number` | `30000` | Replay segment length in ms |
| `recordAllSessions` | `boolean` | `false` | Stream every replay segment and breadcrumb instead of keeping them on the device for error clips. See [Session Replay](/client/js-sdk/session-replay) |
| `sessions` | `boolean` | `true` | Record session start and end. See [Sessions](/learn/sessions) |
| `captureLogs` | `boolean` | `true` | Allow `console.*` output as breadcrumbs |
| `captureNetwork` | `boolean` | `true` | Allow `fetch` / `XHR` calls as CLIENT spans. `false` also stops the `traceparent` header |
| `captureNavigation` | `boolean` | `true` | Allow History API push / replace / pop transitions as breadcrumbs |
| `captureUserActions` | `boolean` | `true` | Allow clicks as breadcrumbs |
| `captureMetrics` | `boolean` | `true` | Allow the [performance metrics](/learn/client-metrics) aggregated on the device |
| `captureHttpServerErrors` | `boolean` | `false` | Report `fetch` / `XHR` responses with status >= 500 as message issues. 4xx is never included |
| `propagateTraceHeaderCorsUrls` | `Array<string \| RegExp>` | none | Cross-origin URLs that get the W3C `traceparent` header (same-origin requests always do) |
| `remoteConfig` | `boolean` | `true` | Fetch collection settings from Traceway, so the **Data Collection** page can change what the app sends without a release. See [Remote SDK Config](/learn/remote-config/setup) |
| `exportDelayMs` | `number` | `1000` | Delay between exports in milliseconds |

The `capture*`, `sessionRecording` and `sessions` options are ceilings: remote settings can restrict a signal further, but never turn on what you turned off here. By default breadcrumbs and replay stay on the device and upload with an error; errors and messages are sent as they happen.

[Initialization](/client/js-sdk/initialization#options-reference) has the full list, including `collection`, `telemetry`, `transport`, `errorLimits` and `collectionLimits`. The 1.x options `debounceMs`, `retryDelayMs`, `eventsWindowMs` and `eventsMaxCount` are gone, see the [migration guide](/client/js-sdk/migration).

## Custom Attributes

Use `<TracewayAttributes>` or the `useTracewayAttributes` hook to bind a reactive map of attributes (`user.id`, `tenant`, feature flags, etc.) to the SDK's global scope. The hook diffs against the previous map on every render and pushes only the deltas; on unmount, every key it currently owns is removed.

```jsx
import { TracewayAttributes, useTracewayAttributes } from "@tracewayapp/react";

// As a component:
<TracewayAttributes attributes={user ? { "user.id": user.id, tenant: org.id } : null} />

// Or as a hook:
function App() {
  useTracewayAttributes(user ? { "user.id": user.id, tenant: org.id } : null);
  return <Routes />;
}
```

Both accept `null` / `undefined` as "empty map", which is useful while user data loads or after logout. Values are strings (`Record<string, string>`), so pass `null` rather than a map with `undefined` values. New object reference with the same content does not trigger SDK calls. The hook removes every key it was given when it unmounts, so do not set the same key with `setAttribute` elsewhere.

For imperative use (background workers, init scripts), the same primitives are exported as plain functions:

```javascript
import { setAttribute, setAttributes, removeAttribute, clearAttributes } from "@tracewayapp/react";

setAttribute("build_channel", import.meta.env.VITE_CHANNEL ?? "dev");
setAttributes({ tenant: "acme", plan: "pro" });
clearAttributes(); // on logout
```

Layering on each event: **defaults < global scope < per-call**. See [Sessions](/learn/sessions) for the full attribute model.

Remote rules can target these attributes. After login, call `refreshConfig()` (also exported from `@tracewayapp/react`) so a rule that targets an attribute such as `user.id` applies at once instead of at the next poll.

## Example with Options

```jsx
<TracewayProvider
  connectionString="your-token@https://traceway.example.com/api/report"
  options={{
    debug: process.env.NODE_ENV === "development",
    version: process.env.REACT_APP_VERSION,
    environment: process.env.NODE_ENV,
  }}
>
  <YourApp />
</TracewayProvider>
```

## Capture All Errors

By default, 4xx HTTP errors, network errors, and timeouts are ignored. To capture everything:

```jsx
<TracewayProvider
  connectionString="your-token@https://traceway.example.com/api/report"
  options={{ ignoreErrors: [] }}
>
  <YourApp />
</TracewayProvider>
```

## Environment-Specific Setup

```jsx
function App() {
  const connectionString = process.env.NODE_ENV === "production"
    ? process.env.REACT_APP_TRACEWAY_PROD
    : process.env.REACT_APP_TRACEWAY_DEV;

  return (
    <TracewayProvider connectionString={connectionString}>
      <YourApp />
    </TracewayProvider>
  );
}
```

## Placement

Place `TracewayProvider` as high as possible in your component tree, typically in your root `App` component or `index.js`:

```jsx
// index.js
import React from "react";
import ReactDOM from "react-dom/client";
import { TracewayProvider } from "@tracewayapp/react";
import App from "./App";

const root = ReactDOM.createRoot(document.getElementById("root"));
root.render(
  <React.StrictMode>
    <TracewayProvider connectionString="your-token@...">
      <App />
    </TracewayProvider>
  </React.StrictMode>
);
```

### A note on StrictMode

`TracewayProvider` initializes the SDK in its constructor, and StrictMode double-invokes constructors in development. That is harmless: `init()` is a no-op while a client is running, so the second call does not create another client or a second set of error handlers. For the same reason a second `TracewayProvider` on the page does not start a second client; the first one's connection string and options stay in effect. The provider can sit inside or outside `<StrictMode>`.

In 1.x the double call created two clients and doubled every dev-mode error. If you moved the provider outside `<StrictMode>` to avoid that, you can leave it there or move it back.

## TracewayContext

For advanced use cases, you can access the context directly:

```jsx
import { TracewayContext } from "@tracewayapp/react";
import { useContext } from "react";

function MyComponent() {
  const traceway = useContext(TracewayContext);
  // Use traceway.captureException, etc.
}
```

However, the `useTraceway` hook is preferred for most use cases.
