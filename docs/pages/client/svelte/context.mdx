# Context Setup

Understanding Traceway's Svelte context integration. The examples use Svelte 5 and SvelteKit.

## How It Works

Traceway uses Svelte's context API to provide error capture functions to your component tree:

1. `setupTraceway()` initializes the SDK and sets context
2. `getTraceway()` retrieves the context in child components

## setupTraceway

Must be called during component initialization (not in an event handler):

```svelte
<script>
  import { PUBLIC_TRACEWAY_TOKEN } from "$env/static/public";
  import { setupTraceway } from "@tracewayapp/svelte";

  let { children } = $props();

  // Correct: called at component initialization
  setupTraceway({
    token: PUBLIC_TRACEWAY_TOKEN,
  });
</script>

{@render children()}
```

**Initialization is synchronous:** `setupTraceway` calls the SDK's `init()` immediately, during component setup, not in `onMount`. Everything captured after that point is recorded, including captures in a child component's setup code that runs before `onMount`. There is no pre-init buffer, so a capture made before `setupTraceway` runs is dropped.

The SDK starts once per page. A later `setupTraceway` call (a nested layout, a remounted root) sets the context again but does not restart the SDK or apply its options. Only after `await shutdown()` does the next call start it again. `setupTraceway` never throws: a build without its token renders the app as usual, with the SDK off and one console warning that says what is missing.

### Options

| Option    | Type                      | Required                                                | Description                                                                                                                                                                                                                 |
| --------- | ------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `token`   | `string`                  | Yes, unless `options.telemetry` is the only destination | The project token, from the project's **Connection** page. Without one, only a `telemetry` destination in `options` receives anything, see [Standalone](/client/js-sdk/initialization#standalone-without-a-traceway-server) |
| `baseUrl` | `string`                  | No                                                      | The Traceway server, only for a self-hosted one. Default `https://cloud.tracewayapp.com`                                                                                                                                    |
| `options` | `TracewayFrontendOptions` | No                                                      | Every other option, passed to the browser SDK's `init()`                                                                                                                                                                    |

The 2.0 `connectionString` field still works, deprecated, with one warning; see [Upgrading from 2.0](/client/js-sdk/migration#upgrading-from-20).

### SDK Options

`options` takes every option of the browser SDK. The ones used most often are below; [Initialization](/client/js-sdk/initialization#options-reference) has the full list.

| Option                            | Type                      | Default                   | Description                                                                                                                                                                                                                                       |
| --------------------------------- | ------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`                         | `string`                  | none                      | Your application version, reported as `service.version`                                                                                                                                                                                           |
| `environment`                     | `string`                  | none                      | Reported as `deployment.environment.name`, e.g. `"production"`                                                                                                                                                                                    |
| `serviceName`                     | `string`                  | the page's host name      | Reported as `service.name`                                                                                                                                                                                                                        |
| `attributes`                      | `Record<string, string>`  | `{}`                      | Initial global attributes, see [Custom Attributes](#custom-attributes)                                                                                                                                                                            |
| `debug`                           | `boolean`                 | `false`                   | Explain what the SDK does with the page's own `console.warn`: the start, remote config applied or rejected, every dropped exception or message and why, and SDK failures it contained. See [Debug Mode](/client/js-sdk/initialization#debug-mode) |
| `ignoreErrors`                    | `Array<string \| RegExp>` | `DEFAULT_IGNORE_PATTERNS` | Error patterns to ignore. Pass `[]` to capture all errors. See [Error Filtering](/client/js-sdk/initialization#error-filtering)                                                                                                                   |
| `beforeCapture`                   | `(captured) => boolean`   | none                      | Receives a `TracewayCapturedError`, `{ error, type, message, isMessage, stack, attributes }`; return `false` to drop it. See [beforeCapture Callback](/client/js-sdk/initialization#beforecapture-callback)                                       |
| `sessionRecording`                | `boolean`                 | `true`                    | Allow session replay at all                                                                                                                                                                                                                       |
| `sessionRecordingSegmentDuration` | `number`                  | `30000`                   | Replay segment length in ms                                                                                                                                                                                                                       |
| `recordAllSessions`               | `boolean`                 | `false`                   | Stream every replay segment and breadcrumb instead of keeping them on the device for error clips. See [Configure Session Capture](/client/svelte/session-capture)                                                                                 |
| `sessions`                        | `boolean`                 | `true`                    | Record session start and end                                                                                                                                                                                                                      |
| `captureLogs`                     | `boolean`                 | `true`                    | Allow `console.*` output and `log()` lines to be collected as breadcrumbs                                                                                                                                                                         |
| `captureNetwork`                  | `boolean`                 | `true`                    | Instrument `fetch` / `XHR`: CLIENT spans and the `traceparent` header                                                                                                                                                                             |
| `captureNavigation`               | `boolean`                 | `true`                    | Allow History API navigation to be collected as breadcrumbs                                                                                                                                                                                       |
| `captureUserActions`              | `boolean`                 | `true`                    | Allow clicks to be collected as breadcrumbs                                                                                                                                                                                                       |
| `captureMetrics`                  | `boolean`                 | `true`                    | Allow the [performance metrics](/learn/client-metrics) aggregated on the device                                                                                                                                                                   |
| `captureHttpServerErrors`         | `boolean`                 | `false`                   | Report `fetch` / `XHR` responses with status >= 500 as message issues                                                                                                                                                                             |
| `propagateTraceHeaderCorsUrls`    | `Array<string \| RegExp>` | none                      | Cross-origin URLs that also get the `traceparent` header                                                                                                                                                                                          |
| `remoteConfig`                    | `boolean`                 | `true`                    | Fetch collection settings from Traceway, see [Remote SDK Config](/learn/remote-config)                                                                                                                                                            |
| `collection`                      | `CollectionSettings`      | SDK defaults              | Local collection policy: signal modes, sampling, replay (`maskAllInputs`, `images`), buffer and triggers. See [Local collection settings](/client/js-sdk/initialization#local-collection-settings)                                                |
| `telemetry`                       | `TelemetryOptions`        | none                      | Send logs, traces and metrics to another OpenTelemetry provider, see [below](#send-telemetry-to-another-opentelemetry-provider)                                                                                                                   |
| `exportDelayMs`                   | `number`                  | `1000`                    | Delay between uploads of queued telemetry, in ms                                                                                                                                                                                                  |

The `capture*`, `sessionRecording` and `sessions` options are ceilings: remote config can restrict what they allow, but never turns on what they switch off.

## getTraceway

Retrieve capture functions in any child component:

```svelte
<script>
  import { getTraceway } from "@tracewayapp/svelte";

  const { captureException, captureExceptionWithAttributes, captureMessage } = getTraceway();
</script>
```

`getTraceway` never throws. Where no ancestor has called `setupTraceway` (an app that calls `init()` itself, or a server render that skipped it), it returns the same functions, which report once the SDK runs and do nothing before. `useTraceway` is an alias of it, for parity with the React and Vue packages.

### Return Value

| Function                                            | Description                                                                                                                                                                 |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `captureException(error, attributes?)`              | Capture an error with stack trace                                                                                                                                           |
| `captureExceptionWithAttributes(error, attributes)` | Capture error with metadata. Attribute values are strings                                                                                                                   |
| `captureMessage(message, attributes?)`              | Send a custom message                                                                                                                                                       |
| `recordAction(category, name, data?)`               | Record a breadcrumb for the replay timeline. It is buffered on the device like the other breadcrumbs and uploaded with the next error, or streamed with `recordAllSessions` |

`setupTraceway` returns the same object.

## Complete Example

Root layout:

```svelte
<!-- src/routes/+layout.svelte -->
<script>
  import { PUBLIC_TRACEWAY_TOKEN } from "$env/static/public";
  import { setupTraceway } from "@tracewayapp/svelte";

  let { children } = $props();

  setupTraceway({
    token: PUBLIC_TRACEWAY_TOKEN,
    options: {
      debug: import.meta.env.DEV,
    },
  });
</script>

{@render children()}
```

Child component:

```svelte
<!-- src/lib/components/Form.svelte -->
<script>
  import { getTraceway } from "@tracewayapp/svelte";

  const { captureExceptionWithAttributes } = getTraceway();

  let formData = $state({ email: "", name: "" });

  async function handleSubmit(event) {
    event.preventDefault();
    try {
      const response = await fetch("/api/submit", {
        method: "POST",
        body: JSON.stringify(formData),
      });
      if (!response.ok) throw new Error("Submission failed");
    } catch (error) {
      captureExceptionWithAttributes(error, { action: "form_submit" });
    }
  }
</script>

<form onsubmit={handleSubmit}>
  <input bind:value={formData.name} placeholder="Name" />
  <input class="traceway-mask" bind:value={formData.email} placeholder="Email" />
  <button type="submit">Submit</button>
</form>
```

Keep personal data such as an email address out of attributes; the `traceway-mask` class keeps it out of the replay too (see [Configure Session Capture](/client/svelte/session-capture#mark-elements-with-a-mask)).

## Custom Attributes

Use `useTracewayAttributes` to bind a reactive map of attributes (`user.id`, `tenant`, feature flags, etc.) to the SDK's global scope. It's a factory: call it once during component setup, then invoke the returned setter from `$effect`. The setter diffs against the last map and pushes only the deltas; `onDestroy` removes every key it currently owns.

```svelte
<script>
  import { useTracewayAttributes } from "@tracewayapp/svelte";

  let { user, org } = $props();

  const sync = useTracewayAttributes();
  $effect(() => sync(user ? { "user.id": String(user.id), tenant: String(org.id) } : null));
</script>
```

The setter accepts `null` / `undefined` as "empty map", which is useful while user data loads or after logout. Attribute values are strings, so convert a numeric id with `String()`. The setter removes every key it set when the component is destroyed, so do not set the same key with `setAttribute` elsewhere. A value the SDK cannot write is skipped; it never breaks the effect.

For imperative use (load functions, hooks), the same primitives are exported as plain functions:

```javascript
import {
  setAttribute,
  setAttributes,
  removeAttribute,
  clearAttributes,
} from "@tracewayapp/svelte";

setAttribute("build_channel", "canary");
setAttributes({ tenant: "acme", plan: "pro" });
clearAttributes(); // on logout
```

Layering on each event: **defaults < global scope < per-call**. See [Sessions](/learn/sessions) for the full attribute model.

## Route Names

Performance metrics are grouped by page. Call `trackRoute` with the route id so they group by route (`/orders/[id]`) and not by URL; the same name is the screen (`app.screen.name`) on exceptions, log lines and clicks. Without it the SDK replaces id-like path segments itself. In SvelteKit, from the root layout:

```svelte
<!-- src/routes/+layout.svelte -->
<script>
  import { page } from "$app/state";
  import { PUBLIC_TRACEWAY_TOKEN } from "$env/static/public";
  import { setupTraceway, trackRoute } from "@tracewayapp/svelte";

  let { children } = $props();

  setupTraceway({
    token: PUBLIC_TRACEWAY_TOKEN,
  });

  $effect(() => {
    page.url.pathname; // Run again for another URL with the same route id.
    trackRoute(page.route.id);
  });
</script>

{@render children()}
```

`trackRoute(null)` clears the name. For navigation the address does not show (a modal, a wizard step), report it with `recordNavigation(path, action, from, route)`; see [Screens and navigation](/client/js-sdk#screens-and-navigation). On a SvelteKit version without `$app/state`, import `page` from `$app/stores` and call `trackRoute($page.route.id)` from a `$effect`.

## Events, Metrics and Lifecycle

The rest of the browser SDK's API is re-exported from `@tracewayapp/svelte`, so nothing has to be imported from `@tracewayapp/frontend`: every value except `init` (`setupTraceway` calls it), the `TracewayFrontendClient` class and `trackRouter`, which this package replaces with `trackRoute`. These are plain functions, not part of the context, and do nothing until `setupTraceway` has run:

| Function                                         | Description                                                                                                                                                                |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `log(message, level?, attributes?)`              | Record a log line of your own, e.g. `log("cart synced", "debug", { items: 3 })`, handled like a `console.*` line. See [Logs](/client/js-sdk#logs)                          |
| `track(eventName, attributes?)`                  | Record a named app event, e.g. `track("checkout_failed", { step: "payment" })`. Buffered on the device by default                                                          |
| `metric(name, value, dims?)`                     | Record one observation of a custom distribution, e.g. `metric("checkout.duration", 840, { plan: "pro" })`. Aggregated on the device; at most two dimensions are kept       |
| `count(name, n?, dims?)`                         | Add to a custom counter, e.g. `count("cart.item_added")`                                                                                                                   |
| `setMetricDimension(key, value)`                 | Set a dimension of your own on every performance metric from now on; `null` removes it. At most two keys with a small set of values each, never a user id                  |
| `setRoute(template)`                             | What `trackRoute` calls                                                                                                                                                    |
| `recordNavigation(path, action?, from?, route?)` | Report a navigation the address does not show. See [Screens and navigation](/client/js-sdk#screens-and-navigation)                                                         |
| `routeFromParams(pathname, params)`              | Infer a route template from a path and the params a router matched in it                                                                                                   |
| `startInteraction(name, attributes?)`            | Trace an interaction explicitly; returns a `TracewayInteraction`, see [Distributed Tracing](/client/js-sdk/distributed-tracing#trace-an-entire-interaction-explicitly)     |
| `tracer()`                                       | The SDK's OpenTelemetry tracer for spans of your own, or `undefined` before `setupTraceway`. See [Spans of your own](/client/js-sdk/distributed-tracing#spans-of-your-own) |
| `refreshConfig()`                                | Fetch this client's [remote settings](/learn/remote-config) now instead of at the next poll, e.g. right after a login set `user.id` with `setAttribute`                    |
| `flush(timeoutMs?)`                              | Send everything that is queued for sending. Buffered telemetry stays on the device. See [Flush](/client/js-sdk/flush)                                                      |
| `shutdown()`                                     | Flush, remove the instrumentations and stop recording. `setupTraceway` may run again afterwards                                                                            |
| `getInstanceId()`                                | The id this browser profile reports as `service.instance.id`, which a dashboard capture can target                                                                         |
| `currentSessionId()`                             | The current session's id (`session.id`), or `null` before `setupTraceway` and between sessions                                                                             |
| `getClient()`                                    | The running `TracewayFrontendClient`, or `null` before `setupTraceway` and on the server                                                                                   |

`captureException`, `captureExceptionWithAttributes`, `captureMessage`, `recordAction`, `DEFAULT_IGNORE_PATTERNS` and `SDK_VERSION` are exported the same way, and so are the types (`TracewayFrontendOptions`, `TracewayCapturedError`, `TracewayInteraction`, `TracewayLogLevel`, `TracewayImagePolicy`, `CollectionSettings` and the others). See [Client Metrics](/learn/client-metrics) for the custom metric rules.

## Send telemetry to another OpenTelemetry provider

The `telemetry` option sends logs, traces and metrics to any OTLP/HTTP endpoint, while errors, replay, captures and remote config stay on Traceway:

```javascript
setupTraceway({
  token: PUBLIC_TRACEWAY_TOKEN,
  options: { telemetry: { url: "https://collector.example.com" } },
});
```

The collector host is an example: use your own. Without a `token` the SDK runs standalone and sends only there. See [Send telemetry to another OpenTelemetry provider](/client/js-sdk/initialization#send-telemetry-to-another-opentelemetry-provider) for per-signal destinations, headers and CORS.

## TRACEWAY_KEY

For advanced use cases, you can access the context key directly:

```svelte
<script>
  import { getContext } from "svelte";
  import { TRACEWAY_KEY } from "@tracewayapp/svelte";

  const traceway = getContext(TRACEWAY_KEY);
</script>
```

## SvelteKit Error Handling

`handleError` in `src/hooks.client.js` is where SvelteKit hands you the real error from a failed `load` or a render crash during client-side navigation. Svelte context is not available in a hook, so import the capture function directly. It is the same function `getTraceway()` returns.

```javascript
// src/hooks.client.js
import { captureExceptionWithAttributes } from "@tracewayapp/svelte";

export function handleError({ error, event }) {
  captureExceptionWithAttributes(error, {
    route: event.route?.id ?? event.url.pathname,
  });
  return { message: "Something went wrong" };
}
```

Do not capture from `+error.svelte`. That page only receives `page.error`, which SvelteKit has already reduced to a plain `{ message }` object. Passing it to `captureException` produces an issue named after the serialized object, such as `Error: {"message":"Internal Error"}`, with the stack of the capture call and no original message. Use the page for display and let `handleError` do the reporting.

```svelte
<!-- src/routes/+error.svelte -->
<script>
  import { page } from "$app/state";
</script>

<h1>Error: {page.status}</h1>
<p>{page.error?.message}</p>
```

### Render Errors

Svelte 5's `<svelte:boundary>` catches errors thrown while its children render. Pass `captureSvelteError` as `onerror` to report them:

```svelte
<script>
  import { captureSvelteError } from "@tracewayapp/svelte";
  import Widget from "$lib/components/Widget.svelte";
</script>

<svelte:boundary onerror={captureSvelteError}>
  <Widget />
  {#snippet failed(error)}
    <p>Something went wrong: {error.message}</p>
  {/snippet}
</svelte:boundary>
```

`captureSvelteError` reports an `Error` with `captureException` and any other thrown value as a message, with `captureMessage(String(err))`. It works without context and never throws. Svelte 4 has no boundary: wrap risky code in `try`/`catch` and call `captureSvelteError(err)` yourself.

## Environment Variables

For SvelteKit, use public environment variables:

```bash
# .env
PUBLIC_TRACEWAY_TOKEN=YOUR_TOKEN
```

```svelte
<script>
  import { PUBLIC_TRACEWAY_TOKEN } from "$env/static/public";
  import { setupTraceway } from "@tracewayapp/svelte";

  let { children } = $props();

  setupTraceway({
    token: PUBLIC_TRACEWAY_TOKEN,
  });
</script>

{@render children()}
```

For a self-hosted server, add `PUBLIC_TRACEWAY_URL` with its address to `.env`, import it next to the token and pass it as `baseUrl`. `$env/static/public` only exports variables that are set at build time, so import it only where it is defined.

## Best Practices

1. **Initialize early**: Call `setupTraceway` in your root layout
2. **Skip the browser guard**: `setupTraceway` must also run during SSR, so the context is set there. On the server it only sets the context: the SDK does not start without `window`
3. **Use attributes**: Add context with `captureExceptionWithAttributes`
4. **Handle gracefully**: Show user-friendly errors while capturing details

```svelte
<script>
  import { getTraceway } from "@tracewayapp/svelte";

  const { captureException } = getTraceway();
  let error = $state(null);

  async function loadData() {
    try {
      const data = await fetchData();
      // use data
    } catch (e) {
      captureException(e);
      error = "Failed to load data. Please try again.";
    }
  }
</script>

{#if error}
  <p class="error">{error}</p>
{/if}
```
