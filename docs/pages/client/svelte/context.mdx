# Context Setup

Understanding Traceway's Svelte context integration.

## How It Works

Traceway uses Svelte's context API to provide error capture functions to your component tree:

1. `setupTraceway()` initializes the SDK and sets context
2. `getTraceway()` retrieves the context in child components

## setupTraceway

Must be called during component initialization (not in an event handler):

```svelte
<script>
  import { setupTraceway } from "@tracewayapp/svelte";

  // Correct: called at component initialization
  setupTraceway({
    connectionString: "your-token@https://traceway.example.com/api/report",
  });
</script>
```

**Initialization is synchronous:** `setupTraceway` calls the SDK's `init()` immediately, during component setup, not in `onMount`. Everything captured after that point is recorded, including captures in a child component's setup code that runs before `onMount`. There is no pre-init buffer, so a capture made before `setupTraceway` runs is dropped.

The SDK starts once per page. A later `setupTraceway` call (a nested layout, a remounted root) sets the context again but does not restart the SDK or apply its options. Only after `await shutdown()` does the next call start it again.

### Options

| Option | Type | Required | Description |
|--------|------|----------|-------------|
| `connectionString` | `string \| StandaloneOptions` | Yes | Your Traceway connection string. An options object with a `telemetry` destination runs the SDK without a Traceway server, see [Local configuration without OpAMP](/client/js-sdk/initialization#standalone-without-a-traceway-server) |
| `options` | `TracewayFrontendOptions` | No | SDK configuration, passed to the browser SDK's `init()` |

### SDK Options

`options` takes every option of the browser SDK. The ones used most often are below; [Initialization](/client/js-sdk/initialization#options-reference) has the full list.

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `version` | `string` | none | Your application version, reported as `service.version` |
| `environment` | `string` | none | Reported as `deployment.environment.name`, e.g. `"production"` |
| `serviceName` | `string` | the page's host name | Reported as `service.name` |
| `attributes` | `Record<string, string>` | `{}` | Initial global attributes, see [Custom Attributes](#custom-attributes) |
| `debug` | `boolean` | `false` | Log a rejected project token and a `beforeCapture` callback that throws to the console |
| `ignoreErrors` | `Array<string \| RegExp>` | `DEFAULT_IGNORE_PATTERNS` | Error patterns to ignore. Pass `[]` to capture all errors. See [Error Filtering](/client/js-sdk/initialization#error-filtering) |
| `beforeCapture` | `({ type, message, stack, attributes }) => boolean` | none | Return `false` to suppress an error. See [Error Filtering](/client/js-sdk/initialization#error-filtering) |
| `sessionRecording` | `boolean` | `true` | Allow session replay at all |
| `sessionRecordingSegmentDuration` | `number` | `30000` | Replay segment length in ms |
| `recordAllSessions` | `boolean` | `false` | Stream every replay segment and breadcrumb instead of keeping them on the device for error clips. See [Session Replay](/client/js-sdk/session-replay) |
| `sessions` | `boolean` | `true` | Record session start and end |
| `captureLogs` | `boolean` | `true` | Allow `console.*` output to be collected as breadcrumbs |
| `captureNetwork` | `boolean` | `true` | Instrument `fetch` / `XHR`: CLIENT spans and the `traceparent` header |
| `captureNavigation` | `boolean` | `true` | Allow History API navigation to be collected as breadcrumbs |
| `captureUserActions` | `boolean` | `true` | Allow clicks to be collected as breadcrumbs |
| `captureMetrics` | `boolean` | `true` | Allow the [performance metrics](/learn/client-metrics) aggregated on the device |
| `captureHttpServerErrors` | `boolean` | `false` | Report `fetch` / `XHR` responses with status >= 500 as message issues |
| `propagateTraceHeaderCorsUrls` | `Array<string \| RegExp>` | none | Cross-origin URLs that also get the `traceparent` header |
| `remoteConfig` | `boolean` | `true` | Fetch collection settings from Traceway, see [Remote SDK Config](/learn/remote-config) |
| `exportDelayMs` | `number` | `1000` | Delay between uploads of queued telemetry, in ms |

The `capture*`, `sessionRecording` and `sessions` options are ceilings: remote config can restrict what they allow, but never turns on what they switch off.

## getTraceway

Retrieve capture functions in any child component:

```svelte
<script>
  import { getTraceway } from "@tracewayapp/svelte";

  const { captureException, captureExceptionWithAttributes, captureMessage } = getTraceway();
</script>
```

`getTraceway` throws when no ancestor has called `setupTraceway`. `useTraceway` is an alias of it, for parity with the React and Vue packages.

### Return Value

| Function | Description |
|----------|-------------|
| `captureException(error, attributes?)` | Capture an error with stack trace |
| `captureExceptionWithAttributes(error, attributes)` | Capture error with metadata. Attribute values are strings |
| `captureMessage(message, attributes?)` | Send a custom message |
| `recordAction(category, name, data?)` | Record a breadcrumb for the replay timeline. It is buffered on the device like the other breadcrumbs and uploaded with the next error, or streamed with `recordAllSessions` |

`setupTraceway` returns the same object.

## Complete Example

Root layout:

```svelte
<!-- src/routes/+layout.svelte -->
<script>
  import { setupTraceway } from "@tracewayapp/svelte";
  import { PUBLIC_TRACEWAY_CONNECTION } from "$env/static/public";

  setupTraceway({
    connectionString: PUBLIC_TRACEWAY_CONNECTION,
    options: {
      debug: import.meta.env.DEV,
    },
  });
</script>

<slot />
```

Child component:

```svelte
<!-- src/lib/components/Form.svelte -->
<script>
  import { getTraceway } from "@tracewayapp/svelte";

  const { captureException, captureExceptionWithAttributes } = getTraceway();

  let formData = { email: "", name: "" };

  async function handleSubmit() {
    try {
      const response = await fetch("/api/submit", {
        method: "POST",
        body: JSON.stringify(formData),
      });
      if (!response.ok) throw new Error("Submission failed");
    } catch (error) {
      captureExceptionWithAttributes(error, {
        email: formData.email,
        action: "form_submit",
      });
    }
  }
</script>

<form on:submit|preventDefault={handleSubmit}>
  <input bind:value={formData.name} placeholder="Name" />
  <input bind:value={formData.email} placeholder="Email" />
  <button type="submit">Submit</button>
</form>
```

## Custom Attributes

Use `useTracewayAttributes` to bind a reactive map of attributes (`user.id`, `tenant`, feature flags, etc.) to the SDK's global scope. It's a factory: call it once during component setup, then invoke the returned setter from `$effect` (Svelte 5) or `$:` (Svelte 4). The setter diffs against the last map and pushes only the deltas; `onDestroy` removes every key it currently owns.

```svelte
<!-- Svelte 5 -->
<script>
  import { useTracewayAttributes } from "@tracewayapp/svelte";
  let { user, org } = $props();
  const sync = useTracewayAttributes();
  $effect(() => sync({ "user.id": user.id, tenant: org.id }));
</script>
```

```svelte
<!-- Svelte 4 -->
<script>
  import { useTracewayAttributes } from "@tracewayapp/svelte";
  export let user; export let org;
  const sync = useTracewayAttributes();
  $: sync({ "user.id": user.id, tenant: org.id });
</script>
```

The setter accepts `null` / `undefined` as "empty map", which is useful while user data loads or after logout. Attribute values are strings, so convert a numeric id with `String()`. The setter removes every key it set when the component is destroyed, so do not set the same key with `setAttribute` elsewhere.

For imperative use (load functions, hooks), the same primitives are exported as plain functions:

```javascript
import { setAttribute, setAttributes, removeAttribute, clearAttributes } from "@tracewayapp/svelte";

setAttribute("build_channel", "canary");
setAttributes({ tenant: "acme", plan: "pro" });
clearAttributes(); // on logout
```

Layering on each event: **defaults < global scope < per-call**. See [Sessions](/learn/sessions) for the full attribute model.

## Route Names

Performance metrics are grouped by page. Call `trackRoute` with the route id so they group by route (`/orders/[id]`) and not by URL; without it the SDK replaces id-like path segments itself. In SvelteKit, from the root layout:

```svelte
<!-- src/routes/+layout.svelte, Svelte 5 -->
<script>
  import { page } from "$app/state";
  import { setupTraceway, trackRoute } from "@tracewayapp/svelte";

  let { children } = $props();

  setupTraceway({
    connectionString: "your-token@https://traceway.example.com/api/report",
  });

  $effect(() => trackRoute(page.route.id));
</script>

{@render children()}
```

On Svelte 4, or a SvelteKit version without `$app/state`, import `page` from `$app/stores` and write `$: trackRoute($page.route.id);`. `trackRoute(null)` clears the name.

## Events, Metrics and Lifecycle

The rest of the browser SDK's API is re-exported from `@tracewayapp/svelte`, so nothing has to be imported from `@tracewayapp/frontend`. These are plain functions, not part of the context, and do nothing until `setupTraceway` has run:

| Function | Description |
|----------|-------------|
| `track(eventName, attributes?)` | Record a named app event, e.g. `track("checkout_failed", { step: "payment" })`. Buffered on the device by default |
| `metric(name, value, dims?)` | Record one observation of a custom distribution, e.g. `metric("checkout.duration", 840, { plan: "pro" })`. Aggregated on the device; at most two dimensions are kept |
| `count(name, n?, dims?)` | Add to a custom counter, e.g. `count("cart.item_added")` |
| `setMetricDimension(key, value)` | Set a dimension of your own on every performance metric from now on; `null` removes it. At most two keys with a small set of values each, never a user id |
| `setRoute(template)` | What `trackRoute` calls |
| `startInteraction(name)` | Trace an interaction explicitly, see [Distributed Tracing](/client/js-sdk/distributed-tracing#trace-an-entire-interaction-explicitly) |
| `refreshConfig()` | Fetch this client's [remote settings](/learn/remote-config) now instead of at the next poll, e.g. right after a login set `user.id` with `setAttribute` |
| `flush(timeoutMs?)` | Send everything that is queued for sending. Buffered telemetry stays on the device. See [Flush](/client/js-sdk/flush) |
| `shutdown()` | Flush, remove the instrumentations and stop recording. `setupTraceway` may run again afterwards |
| `getInstanceId()` | The id this browser profile reports as `service.instance.id`, which a dashboard capture can target |

`captureException`, `captureExceptionWithAttributes`, `captureMessage`, `recordAction` and `DEFAULT_IGNORE_PATTERNS` are exported the same way. See [Client Metrics](/learn/client-metrics) for the custom metric rules.

## TRACEWAY_KEY

For advanced use cases, you can access the context key directly:

```svelte
<script>
  import { getContext } from "svelte";
  import { TRACEWAY_KEY } from "@tracewayapp/svelte";

  const traceway = getContext(TRACEWAY_KEY);
</script>
```

## SvelteKit Error Handling

`handleError` in `src/hooks.client.js` is where SvelteKit hands you the real error from a failed `load` or a render crash during client-side navigation. Svelte context is not available in a hook, so import the capture function directly. It is the same function `getTraceway()` returns.

```javascript
// src/hooks.client.js
import { captureExceptionWithAttributes } from "@tracewayapp/svelte";

export function handleError({ error, event }) {
  captureExceptionWithAttributes(error, {
    route: event.route?.id ?? event.url.pathname,
  });
  return { message: "Something went wrong" };
}
```

Do not capture from `+error.svelte`. That page only receives `$page.error`, which SvelteKit has already reduced to a plain `{ message }` object. Passing it to `captureException` produces an issue named after the serialized object, such as `Error: {"message":"Internal Error"}`, with the stack of the capture call and no original message. Use the page for display and let `handleError` do the reporting.

```svelte
<!-- src/routes/+error.svelte -->
<script>
  import { page } from "$app/stores";
</script>

<h1>Error: {$page.status}</h1>
<p>{$page.error?.message}</p>
```

### Render Errors (Svelte 5)

Svelte 5's `<svelte:boundary>` catches errors thrown while its children render. Pass `captureSvelteError` as `onerror` to report them:

```svelte
<script>
  import { captureSvelteError } from "@tracewayapp/svelte";
  import Widget from "$lib/components/Widget.svelte";
</script>

<svelte:boundary onerror={captureSvelteError}>
  <Widget />
  {#snippet failed(error)}
    <p>Something went wrong: {error.message}</p>
  {/snippet}
</svelte:boundary>
```

## Best Practices

1. **Initialize early**: Call `setupTraceway` in your root layout
2. **Skip the browser guard**: `setupTraceway` must also run during SSR, or `getTraceway()` throws in child components. On the server it only sets the context: the SDK does not start without `window`
3. **Use attributes**: Add context with `captureExceptionWithAttributes`
4. **Handle gracefully**: Show user-friendly errors while capturing details

```svelte
<script>
  import { getTraceway } from "@tracewayapp/svelte";

  const { captureException } = getTraceway();
  let error = null;

  async function loadData() {
    try {
      const data = await fetchData();
      // use data
    } catch (e) {
      captureException(e);
      error = "Failed to load data. Please try again.";
    }
  }
</script>

{#if error}
  <p class="error">{error}</p>
{/if}
```
