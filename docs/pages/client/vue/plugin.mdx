# Plugin Setup

Configure the Traceway Vue plugin with `createTracewayPlugin`.

## Basic Setup

```javascript
import { createApp } from "vue";
import { createTracewayPlugin } from "@tracewayapp/vue";
import App from "./App.vue";

const app = createApp(App);

app.use(createTracewayPlugin({
  connectionString: "your-token@https://traceway.example.com/api/report",
}));

app.mount("#app");
```

## Plugin Options

| Option | Type | Required | Description |
|--------|------|----------|-------------|
| `connectionString` | `string \| StandaloneOptions` | Yes | Your Traceway connection string. An options object with a `telemetry` destination runs the SDK [without a Traceway server](/client/js-sdk/initialization#standalone-without-a-traceway-server) |
| `options` | `TracewayFrontendOptions` | No | SDK configuration options, passed to `init()` |

The plugin calls `init()` when it is installed. The SDK starts once per page: another `init()` is a no-op until `await shutdown()`. When `connectionString` is an options object, it carries the SDK options itself and `options` is ignored.

## SDK Options

`options` takes every option of the browser SDK. The ones used most:

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `debug` | `boolean` | `false` | Log the problems the SDK would otherwise swallow (a `beforeCapture` that throws, a rejected project token). The plugin also prints every error its `errorHandler` catches, see [Automatic Error Handling](#automatic-error-handling) |
| `version` | `string` | none | Your application version, reported as `service.version` |
| `environment` | `string` | `undefined` | `deployment.environment.name`, e.g. `"production"` |
| `serviceName` | `string` | the page's host name | `service.name` of this app |
| `ignoreErrors` | `Array<string \| RegExp>` | `DEFAULT_IGNORE_PATTERNS` | Error patterns to ignore. Pass `[]` to capture all errors. See [Error Filtering](/client/js-sdk/initialization#error-filtering) |
| `beforeCapture` | `({ type, message, stack, attributes }) => boolean` | `undefined` | Return `false` to suppress an error. See [Error Filtering](/client/js-sdk/initialization#error-filtering) |
| `sessionRecording` | `boolean` | `true` | Allow rrweb session replay at all |
| `sessionRecordingSegmentDuration` | `number` | `30000` | Replay segment length in ms |
| `recordAllSessions` | `boolean` | `false` | Stream every replay segment and breadcrumb instead of keeping them on the device for error clips. See [Session Replay](/client/js-sdk/session-replay) |
| `captureLogs` | `boolean` | `true` | Allow `console.*` calls as breadcrumbs |
| `captureNetwork` | `boolean` | `true` | Allow `fetch` / `XHR` calls as CLIENT spans |
| `captureNavigation` | `boolean` | `true` | Allow navigation breadcrumbs (page loads and History API transitions) |
| `captureUserActions` | `boolean` | `true` | Allow click breadcrumbs |
| `captureMetrics` | `boolean` | `true` | Allow the [performance metrics](/learn/client-metrics) aggregated on the device |
| `propagateTraceHeaderCorsUrls` | `Array<string \| RegExp>` | `undefined` | Cross-origin URLs that receive the W3C `traceparent` header (same-origin requests always do) |
| `remoteConfig` | `boolean` | `true` | Fetch collection settings from Traceway, so the **Data Collection** page can change what the app sends without a release. See [Remote SDK Config](/learn/remote-config) |
| `exportDelayMs` | `number` | `1000` | Delay between uploads of streamed telemetry, in ms |

The `capture*` and `sessionRecording` options are ceilings: remote settings can restrict a signal further, but never turn on what the app turned off. See [Initialization](/client/js-sdk/initialization#options-reference) for the full list.

By default errors and messages are sent as they happen, while console, network, navigation and click breadcrumbs and the replay stay on the device. A captured error uploads up to 10 minutes of those breadcrumbs and a 30-second replay clip.

## Full Example

```javascript
import { createApp } from "vue";
import { createTracewayPlugin } from "@tracewayapp/vue";
import App from "./App.vue";

const app = createApp(App);

app.use(createTracewayPlugin({
  connectionString: "your-token@https://traceway.example.com/api/report",
  options: {
    debug: import.meta.env.DEV,
    version: import.meta.env.VITE_APP_VERSION,
    environment: import.meta.env.MODE,
  },
}));

app.mount("#app");
```

## Capture All Errors

By default, 4xx HTTP errors, network errors, and timeouts are ignored. To capture everything:

```javascript
app.use(createTracewayPlugin({
  connectionString: "your-token@https://traceway.example.com/api/report",
  options: {
    ignoreErrors: [],
  },
}));
```

## Automatic Error Handling

The plugin automatically installs `app.config.errorHandler` to capture:

- Component rendering errors
- Watcher errors
- Lifecycle hook errors

```javascript
// This is handled automatically by the plugin:
app.config.errorHandler = (err, instance, info) => {
  // Error is captured and sent to Traceway
};
```

A thrown value that is not an `Error` is reported as a message, with `captureMessage(String(err))`. With `debug: true` the handler also prints the error, the component instance and Vue's info string with `console.error`.

Uncaught errors and unhandled promise rejections outside Vue are captured by the SDK's own global handlers, see [Auto-Capture Behavior](/client/js-sdk/initialization#auto-capture-behavior).

Vue has a single `app.config.errorHandler` slot, and the plugin assigns it. If your app assigns its own handler after `app.use(createTracewayPlugin(...))`, it replaces Traceway's and component errors stop reaching the dashboard. To keep both, capture the error yourself inside your handler:

```javascript
import { captureException, captureMessage } from "@tracewayapp/vue";

app.use(createTracewayPlugin({
  connectionString: "your-token@https://traceway.example.com/api/report",
}));

app.config.errorHandler = (err, instance, info) => {
  if (err instanceof Error) {
    captureException(err);
  } else {
    captureMessage(String(err));
  }
  myOwnErrorReporter(err, info);
};
```

## Route Names

Performance metrics are grouped by page, and a page is named by its matched route pattern (`/orders/:id`), not by its URL. With a browser SDK version 2.0.1 or later there is nothing to set up: the plugin takes Vue Router from the app it is installed in, whichever of the two is installed first, and Nuxt works the same way. Nuxt writes the patterns of its file routes with a trailing `()` (`pages/orders/[id].vue` is `/orders/:id()`, a catch-all is `/docs/:slug(.*)*`), and that is the name the page gets.

On 2.0.0, or for a router that is not installed in the app, pass your `vue-router` instance to `trackRouter` once, after creating it:

```javascript
import { createApp } from "vue";
import { createRouter, createWebHistory } from "vue-router";
import { createTracewayPlugin, trackRouter } from "@tracewayapp/vue";
import App from "./App.vue";
import { routes } from "./routes";

const router = createRouter({ history: createWebHistory(), routes });
trackRouter(router);

const app = createApp(App);

app.use(createTracewayPlugin({
  connectionString: "your-token@https://traceway.example.com/api/report",
}));
app.use(router);

app.mount("#app");
```

Without it the SDK replaces id-like path segments itself (`/orders/8841` becomes `/orders/:id`). See [Client Metrics](/learn/client-metrics).

## Environment-Specific Configuration

```javascript
const connectionString = import.meta.env.PROD
  ? import.meta.env.VITE_TRACEWAY_PROD
  : import.meta.env.VITE_TRACEWAY_DEV;

app.use(createTracewayPlugin({
  connectionString,
  options: {
    debug: import.meta.env.DEV,
  },
}));
```

## Custom Attributes

Attach app-level identifiers (`user.id`, `tenant`, feature flags, etc.) to every session and exception. The `useTracewayAttributes` composable is the Vue way to do it. Pass a getter and it tracks reactive state, pushes only the keys that changed, and removes the keys it owns when the component unmounts:

```vue
<script setup>
import { useTracewayAttributes } from "@tracewayapp/vue";
import { useUser } from "./auth";

const { user, org } = useUser();
useTracewayAttributes(() =>
  user.value && org.value
    ? { "user.id": String(user.value.id), tenant: String(org.value.id) }
    : null
);
</script>
```

Attribute values are strings. The argument can also be a ref or a plain map. Return `null` when there is nothing to attach. The composable then removes the keys it had set.

There is a declarative wrapper for the same thing. It renders nothing and removes its keys on unmount:

```vue
<script setup>
import { TracewayAttributes } from "@tracewayapp/vue";
import { useUser } from "./auth";

const { user, org } = useUser();
</script>

<template>
  <TracewayAttributes
    v-if="user && org"
    :attributes="{ 'user.id': String(user.id), tenant: String(org.id) }"
  />
</template>
```

Treat every key you pass to the composable or the component as owned by it. Do not set the same key with `setAttribute` elsewhere, because the unmount cleanup will remove it.

You can also drive the scope imperatively from `watchEffect`:

```vue
<script setup>
import { watchEffect } from "vue";
import { setAttributes, removeAttribute } from "@tracewayapp/vue";
import { useUser } from "./auth";

const { user, org } = useUser();
watchEffect(() => {
  if (user.value && org.value) {
    setAttributes({ "user.id": String(user.value.id), tenant: String(org.value.id) });
  } else {
    removeAttribute("user.id");
    removeAttribute("tenant");
  }
});
</script>
```

Use `removeAttribute` per key here rather than `clearAttributes()`. `clearAttributes()` empties the whole global scope, so it also drops keys set by other parts of the app.

The full API (`setAttribute`, `setAttributes`, `removeAttribute`, `clearAttributes`) is re-exported from `@tracewayapp/vue`. Layering on each event: **defaults < global scope < per-call**. See [Sessions](/learn/sessions) for the full attribute model.

## Manual Injection

For advanced use cases, you can use the injection key directly:

```vue
<script setup>
import { inject } from "vue";
import { TracewayKey } from "@tracewayapp/vue";

const traceway = inject(TracewayKey);
traceway.captureException(new Error("Manual capture"));
</script>
```

However, the `useTraceway` composable is preferred for most use cases.

## Vite Configuration

Add your connection string to `.env`:

```
VITE_TRACEWAY_CONNECTION=your-token@https://traceway.example.com/api/report
```

Use in your app:

```javascript
app.use(createTracewayPlugin({
  connectionString: import.meta.env.VITE_TRACEWAY_CONNECTION,
}));
```

## Nuxt Integration

For Nuxt 3, create a plugin:

```javascript
// plugins/traceway.ts
import { createTracewayPlugin } from "@tracewayapp/vue";

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(createTracewayPlugin({
    connectionString: useRuntimeConfig().public.tracewayConnection,
  }));
});
```

Name the file `traceway.ts`, not `traceway.client.ts`. A `.client` plugin never runs during SSR, so the injection key is missing on the server and the first component calling `useTraceway()` fails the render with `useTraceway must be used within a Vue app that has installed the Traceway plugin` (HTTP 500). The plugin is safe to run universally: it only installs the browser handlers and the recorder when `window` exists, so the server pass just provides the injection key.

Add to `nuxt.config.ts`:

```typescript
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      tracewayConnection: process.env.TRACEWAY_CONNECTION,
    },
  },
});
```
