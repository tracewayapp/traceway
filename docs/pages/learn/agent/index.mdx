# Fix Agent

import { Callout } from "nextra/components";

The fix agent turns an issue into a draft pull request. Press **Fix it** on an issue, and a coding agent clones the repository into a sandbox, reads the issue through the [traceway CLI](/learn/cli) with a read-only token scoped to that one attempt, edits the code, runs your tests, and pushes a branch. You review the pull request like any other.

Traceway never calls a model itself. The agent runs as a separate process in a sandbox, with your provider key and nothing else of the server's environment. The backend only holds the state: the queue, the conversation, the diff and the report.

## The three pieces

| Piece | Where | What it needs |
|-------|-------|---------------|
| **Repository** | Agent page, Repository tab, one per project | The code host integration (a GitHub token today), owner and name, the branch to start from, optionally a test command |
| **Agent profile** | Settings, one or more per organization | Which agent runs (Claude Code), the model, the provider key, and limits on turns, minutes and dollars |
| **Executor** | The server, or a runner fleet later | `AGENT_MODE=embedded` on the `:agent` image, which carries the agent, git and the sandbox |

The preflight dialog behind **Fix it** shows which of these is missing and links to where to fix it.

## The thread

Every attempt has one conversation, the thread, visible on the run page. The agent posts its findings and its questions there; when it asks something, the attempt waits for an answer and the sidebar badge counts it. Answer on the run page or, with the [Slack integration](/learn/agent/slack), in the Slack thread under the alert. Both surfaces show the same messages, each labelled with where it came from.
