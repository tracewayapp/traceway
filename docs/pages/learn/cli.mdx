# CLI

import { Callout } from "nextra/components";

`traceway` is a command-line client for the Traceway HTTP API: exceptions, logs, endpoints, tasks, traces, metrics, monitors, alerts, on-call pages, post-mortems and remote SDK config rules from a terminal. It is read only. Changes go through the separate `traceway-write` CLI described in [Agent Write Access](/learn/agent-write-access). It is designed to be first-class for both humans (with `gh`-style ergonomics) and LLM agents invoking it via shell tools: JSON output when piped, stable error identifiers and exit codes, and nothing that hangs waiting for input. For a quick tour, see the [CLI product page](https://tracewayapp.com/product/cli).

## Installation

### One-line install (macOS, Linux)

```bash
curl -fsSL https://cli.tracewayapp.com/install.sh | sh
```

Add `-s -- --write` to install `traceway-write` instead (see [Agent Write Access](/learn/agent-write-access)). The installer detects your OS and architecture, downloads the latest CLI release from GitHub, verifies its sha256 checksum, and installs `traceway` to `/usr/local/bin` (when writable) or `~/.local/bin`, without sudo. Two environment variables tweak it: `TRACEWAY_CLI_VERSION` pins a version (e.g. `1.9.3`) and `TRACEWAY_INSTALL_DIR` overrides the target directory.

### Prebuilt binaries

Every release publishes prebuilt binaries at [github.com/tracewayapp/traceway/releases](https://github.com/tracewayapp/traceway/releases) under the matching `CLI vX.Y.Z` tag (the CLI version tracks the backend release). Download the archive for your platform (`traceway_<version>_<os>_<arch>.tar.gz`, or `.zip` on Windows), extract it, and put `traceway` on your `PATH`. This is also the route for Windows, which the install script doesn't cover.

### From source

The `cli/` directory of the [main repo](https://github.com/tracewayapp/traceway) ships a Nix dev shell with everything needed:

```bash
cd cli
nix develop
just build         # produces ./bin/traceway
```

Or with vanilla Go:

```bash
go build -o bin/traceway ./cmd/traceway
```

Verify an installed binary with `traceway version` (source builds report `dev`).

## Quick start

```bash
# 1. log in: prints a URL + short code, you approve in the browser
traceway login --url https://cloud.tracewayapp.com

# 2. pick a project (one-time; future calls use it implicitly)
traceway projects list
traceway projects use <project-id>

# 3. ask questions
traceway exceptions list --since 24h
traceway logs query --since 1h --search "OutOfMemory"
traceway endpoints list --since 1h
traceway metrics query --name http.server.duration --aggregation avg --since 1h
```

The default `traceway login` runs a browser device flow with an auto-refreshing token, so you stay logged in for up to 90 days of inactivity. Password login (`--password`) and personal access tokens (`--token`) are also supported; see [CLI Authentication](/learn/cli-auth) for all three modes, and for what to use in CI.

## Commands

| Command | Purpose |
|---|---|
| `traceway login` | Authenticate and store a token (device flow, `--password`, or `--token`) |
| `traceway logout` | Revoke the session server-side and forget stored credentials |
| `traceway profiles {list,use}` | Manage multiple Traceway accounts/instances |
| `traceway projects {list,use}` | List or select the active project |
| `traceway exceptions list` | Recent grouped exceptions |
| `traceway exceptions show <hash>` | A single exception group + occurrences; takes the full hash or a unique prefix of 4 or more hex characters |
| `traceway exceptions occurrence <id> --recorded-at <t>` | A single occurrence by id (+ `sessionId` and recording) |
| `traceway logs query` | Query logs with severity / service / search filters |
| `traceway endpoints list` | Per-endpoint p50/p95/p99 stats |
| `traceway endpoints show <id> --recorded-at <t>` | A single request (transaction) by id: spans + linked errors |
| `traceway tasks show <id> --recorded-at <t>` | A single background task run by id |
| `traceway ai-traces show <id> --recorded-at <t>` | A single AI trace by id + its conversation |
| `traceway sessions list` | Sessions that started in the window, with id, start, duration, version, replay and user (`--search` by session id, client IP or an attribute value such as a user id) |
| `traceway sessions show <id> [--started-at <t>]` | A single session by id + the exceptions that fired in it; without `--started-at` the start is looked up among the last 30 days |
| `traceway traces show <id> --recorded-at <t>` | A distributed trace: every service node sharing the id |
| `traceway metrics query` | Time-series metric queries, including `rate`, `last`, and percentiles or `good_ratio` of a distribution metric; `--whole-range` returns one value for the window |
| `traceway metrics discover` | Recorded metric names, types, units and tag keys; `--name M --key K` discovers tag values |
| `traceway dashboards {list,library,export}` | Applied dashboards, shared project assignments and importable JSON |
| `traceway dashboards validate --file F` | Offline dashboard validation without login |
| `traceway pages {list,show}` | On-call pages (`--status active\|open\|acknowledged\|resolved`) |
| `traceway alerts list` | Alert rules with their enabled and snoozed state |
| `traceway slos list` / `slos show <id>` / `slos series <id> --file F` / `slos preview --file F` | [SLOs](/learn/slos#manage-slos-with-the-cli-or-mcp): definition, status, current SLI and error budget, history, and a dry run of a definition |
| `traceway monitors {list,show}` | Uptime monitors and their incidents |
| `traceway post-mortems {list,show}` | Post-mortem documents (`--search`, `--tag`) |
| `traceway opamp rules list` | A browser project's [remote SDK config](/learn/remote-config) rules, in order, with their `updatedAt` |
| `traceway opamp preview --file client.json` | The settings document the saved rules give a client: `{"attributes": {...}, "instanceUid": "..."}` from a file, or `-` for stdin |
| `traceway mcp` | Serve the [MCP server](/learn/mcp) over stdio |

Run `traceway <command> --help` for full per-command flags.

<Callout type="info">
  The `show` / `occurrence` commands take a UUID plus a **required** timestamp flag (`--recorded-at`). Telemetry tables are partitioned by day; the timestamp bounds the query so the lookup prunes partitions instead of scanning all of them. Get the id and its timestamp together: from a dashboard URL's `?t=` param, a notification's `Occurred at`, or a list row's `recordedAt`. Omitting the flag exits 2 (`usage_error`). `sessions show` is the exception: `--started-at` is optional, and without it the CLI looks the start up among the last 30 days' sessions first (one more query; pass it when you know it).
</Callout>

## Profiles

Multiple Traceway instances or accounts coexist via profiles. Configuration (URL, username) lives in `$XDG_CONFIG_HOME/traceway/config.json` so it can be checked in or managed declaratively; credentials and the active project live in `$XDG_STATE_HOME/traceway/state.json`.

```bash
traceway login --url https://traceway.mycompany.com --profile work   # a self-hosted instance
traceway profiles list
traceway profiles use work
traceway --profile personal exceptions list   # one-off override
```

## Output formats

The `--output` flag picks the format. The default is `table` on a TTY and `json` otherwise, so piping always gets machine-readable output.

| Format | Use |
|---|---|
| `table` | Human-friendly columns (default on TTY) |
| `json` | Compact JSON, one record per line (default when stdout isn't a TTY) |
| `yaml` | YAML rendering of the same data |

`--fields a,b,c` projects list responses to just those keys:

```bash
traceway exceptions list --output json --fields exceptionHash,count,lastSeen
```

## Errors and exit codes

Every error writes a stable JSON envelope to stderr (in `json` / `yaml` modes; prose in `table` mode):

```json
{"error":"token_expired","message":"session expired or invalid","hint":"traceway login","exit_code":4}
```

The `error` field is a stable snake_case identifier that scripts and LLMs can branch on. Exit codes:

| Exit | Meaning |
|---|---|
| 0 | Success |
| 1 | Generic / API error |
| 2 | Usage error (bad flags, missing confirmation, invalid time range) |
| 3 | Connection failure |
| 4 | Auth failure (`not_authenticated`, `token_expired`, `forbidden`) |
| 5 | Not found |
| 6 | Rate limited |
| 7 | Server (5xx) |

## Write commands

`traceway` changes nothing. Its write commands (`exceptions archive`, `pages ack`, `alerts snooze` and the rest) exist only in `traceway-write`, a separate binary with its own login. Running one of them in `traceway` fails with `write_required` (exit 2). `opamp rules create`, `update`, `delete` and `reorder`, which change remote SDK config rules, are also only in `traceway-write`. Install the write CLI with:

```bash
curl -fsSL https://cli.tracewayapp.com/install.sh | sh -s -- --write
```

Every `traceway-write` write requires explicit consent:

- Pass `--yes` to skip the prompt.
- Or set `TRACEWAY_ASSUME_YES=1` in the environment.
- Or run interactively and answer the `Continue? [y/N]` prompt.

Calling a mutating command from a non-TTY context (script, LLM tool call) without one of the opt-ins fails immediately with `usage_error` (exit 2); no hung prompts.

## MCP server

`traceway mcp` serves the whole query/debug surface as an MCP server on stdio for clients like Claude Code, Claude Desktop, and Cursor, reusing the CLI session and current project. See [MCP Server](/learn/mcp) for the stdio setup, the zero-install remote server every backend hosts at `/mcp`, and headless use via `TRACEWAY_URL` + `TRACEWAY_TOKEN`.

## Build dashboards

Use `traceway-write dashboards import --file dashboard.json --yes` to create and apply dashboards to the selected project. Add `--mode upsert` to replace definitions by organization-wide name; edits affect every assigned project. Both CLI editions can validate files offline with `dashboards validate --file dashboard.json`. See [Dashboards](/learn/dashboards#build-dashboards-with-the-cli-or-an-ai-agent) for discovery, chart selection, JSON examples and verification.

`traceway-write dashboards embed <id> --yes` issues an expiring read-only link to a dashboard of the selected project and prints it as `url`. Add `--timeframe 7d` or `--from`/`--to` for the range, `--tag account_id=acme` (repeatable) to limit every widget to a tag value, `--expires-in-days N` (1 to 90) or `--expires-at` for the lifetime (five minutes by default) and `--theme light|dark`. The output holds the signed token, so treat it like a credential. See [Share and embed a dashboard](/learn/dashboards#share-and-embed-a-dashboard).


`traceway-write tokens create --name "Acme embed" --yes` creates a read-only personal access token (`twp_`) for your account and prints it once; it never expires unless you add `--expires-in-days N`. Write tokens can only be created in the dashboard. `traceway-write tokens list` shows your tokens' names, prefixes, scopes and expiry, never the tokens.

## Alerting and on-call configuration

`traceway-write` provides `channels`, `alerts`, `slos`, `teams`, `schedules`, `escalation-policies`, `contact-methods` and `notification-chains` commands for configuration, plus `notification-history` and `oncall` for verification. Reads are available in the read-only edition too. Use `--file` JSON for request bodies, `--organization <id>` for organization resources, and a selected project for all writes. `<resource> validate <action> --file F` validates the request envelope offline; the server validates nested settings and permissions. See [alerting examples](/learn/alerts#configure-alerting-with-the-cli-or-mcp), [on-call examples](/learn/on-call#configure-on-call-with-the-cli-or-mcp) and [Agent Write Access](/learn/agent-write-access).
