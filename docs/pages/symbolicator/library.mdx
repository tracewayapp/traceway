# Library

Traceway's JS symbolicator is an importable Go library. Everything the ingest pipeline uses to turn minified stack traces back into source locations (source map parsing, bundle scope analysis for function names, the [`.tw` resolver format](/symbolicator#the-tw-resolver-format), and the mmap-backed disk cache) lives in public packages of the backend module, so you can use the engine in your own tooling without running Traceway at all.

It's pure Go by default: no cgo, no C libraries, works in a `scratch` image.

If you want this functionality inside an OpenTelemetry Collector pipeline instead of your own code, use the [collector processor](/symbolicator/opentelemetry). For how the engine works internally, see [Architecture](/symbolicator) and [JavaScript](/symbolicator/javascript).

## Installation

```bash
go get github.com/tracewayapp/traceway/backend/v2@latest
```

| Package | Import path | Purpose |
| ------- | ----------- | ------- |
| `sourcemap` | `github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap` | The resolver: source map + bundle in, original locations out |
| `jsstack` | `github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap/jsstack` | Browser stack trace parsing (V8, Firefox, Safari formats) |
| `scopes` | `github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap/scopes` | Bundle parser selection (goja default, oxc optional) |
| `twcache` | `github.com/tracewayapp/traceway/backend/v2/app/symbolicator/twcache` | Mmap-backed disk cache of compiled `.tw` resolvers |
| `otelprocessor` | `github.com/tracewayapp/traceway/backend/v2/app/symbolicator/otelprocessor` | The [OTel Collector processor](/symbolicator/opentelemetry) wrapping the engine |

## Resolving a single frame

Build a resolver from a source map and (optionally) its minified bundle, then look positions up. The bundle is what enables function names through scope analysis; pass `nil` and you still get files, lines, and columns.

```go
package main

import (
	"fmt"
	"os"

	"github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap"
)

func main() {
	mapBytes, err := os.ReadFile("dist/app.min.js.map")
	if err != nil {
		panic(err)
	}
	bundleBytes, _ := os.ReadFile("dist/app.min.js") // optional, enables function names

	artifact, err := sourcemap.BuildTW(mapBytes, bundleBytes)
	if err != nil {
		panic(err)
	}

	// LookupTW takes zero-based generated positions. A browser frame like
	// "app.min.js:1:13337" is line 0, column 13336 here.
	frame, ok := sourcemap.LookupTW(artifact, 0, 13336)
	if !ok {
		fmt.Println("no mapping at this position")
		return
	}
	fmt.Printf("%s:%d:%d", frame.File, frame.Line, frame.Col) // src/render.ts:42:7
	if frame.Fn != "" {
		fmt.Printf(" in %s()", frame.Fn)
	}
	fmt.Println()
}
```

The coordinate conventions, precisely:

- `LookupTW(artifact, genLine, genCol)` takes **zero-based** positions, matching the source map spec's internal encoding.
- Browser stack traces print **one-based** positions, so subtract 1 from each before calling `LookupTW`.
- The returned `StackTraceFrame` carries **one-based** `Line` and `Col`, ready to print.
- `Fn` is the enclosing original function name, or `""` when the bundle was not provided or the position is not inside a known scope.

## Symbolicating a whole stack trace

`jsstack.ParseFrames` parses the raw `error.stack` formats browsers actually produce: V8 (`at fn (url:line:col)`, including `async`, `new`, `[as alias]`, and `eval` frames), Firefox, and Safari (`fn@url:line:col`). It returns frames with the one-based positions as printed.

```go
package main

import (
	"fmt"

	"github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap"
	"github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap/jsstack"
)

func symbolicateStack(rawStack string, artifactFor func(url string) []byte) {
	for _, f := range jsstack.ParseFrames(rawStack) {
		artifact := artifactFor(f.URL)
		if artifact == nil || f.Line == 0 || f.Col == 0 {
			continue
		}
		frame, ok := sourcemap.LookupTW(artifact, f.Line-1, f.Col-1)
		if !ok {
			continue
		}
		name := frame.Fn
		if name == "" {
			name = f.Function
		}
		fmt.Printf("%s at %s:%d:%d\n", name, frame.File, frame.Line, frame.Col)
	}
}
```

`artifactFor` is yours to implement: typically a map from bundle URL basename to the resolver built from that bundle's artifacts.

If you need Traceway's canonical frame format (function name on one line, `    file:line:col` on the next, the format described in [JavaScript](/symbolicator/javascript#the-frame-format)), use `jsstack.Canonicalize`:

```go
canonical, converted := jsstack.Canonicalize(rawStack)
```

It returns the input unchanged (`converted == false`) when the trace is not a recognizable browser stack, so it's safe to call on arbitrary text, including Go panics and already-canonical traces.

## Caching compiled resolvers: the `.tw` format

The bytes returned by `sourcemap.BuildTW` are the complete [`.tw` artifact](/symbolicator#the-tw-resolver-format). Save them to reuse the mapping across restarts. To check a stored artifact before reuse, call `sourcemap.ValidTW`.

For a byte-bounded disk cache, open the directory once and use a build-specific key. On a cache miss, `Get` invokes your loader. Keep the returned bytes until the lookup finishes, then call the release function so the cache can unmap the file.

```go
package main

import (
	"context"

	"github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap"
	"github.com/tracewayapp/traceway/backend/v2/app/symbolicator/twcache"
)

func newCache(dir string) (*twcache.Cache[[]byte], error) {
	cache, err := twcache.NewDisk(dir, 2<<30, nil)
	if err != nil {
		return nil, err
	}
	cache.Validate = sourcemap.ValidTW
	return cache, nil
}

func lookup(ctx context.Context, cache *twcache.Cache[[]byte], key string,
	load twcache.LoadFunc[[]byte], line, col uint32) (sourcemap.StackTraceFrame, bool, error) {
	artifact, release, err := cache.Get(ctx, key, load)
	if err != nil {
		return sourcemap.StackTraceFrame{}, false, err
	}
	defer release()
	frame, ok := sourcemap.LookupTW(artifact, line, col)
	return frame, ok, nil
}
```

The loader can read the map and bundle and return `sourcemap.BuildTW(mapBytes, bundleBytes)`. Name entries relative to the cache directory with a `.tw` suffix so the startup scan discovers them. Use `Invalidate(key)` when replacing an artifact under the same name. To cache the bytes on the heap, construct the cache with `twcache.NewMem(maxEntries, maxBytes)`.

## Choosing the bundle parser

Function-name resolution parses the minified bundle into scopes. Two parsers produce identical output (a parity test asserts this across the fixture suite, see [Bundle parsers](/symbolicator/javascript#bundle-parsers)):

- **goja** (default): pure Go, zero setup.
- **oxc**: a Rust parser behind cgo, several times faster on large bundles. The `-tags oxc` build links a static library from the `scopes` package's own source directory (`oxc-shim/target/release/liboxc_shim.a`), which the read-only module cache that `go get` populates never contains. To enable it, build against a writable checkout: clone the repo, run `scripts/build-oxc-shim.sh` once, add a `replace github.com/tracewayapp/traceway/backend/v2 => /path/to/traceway/backend` directive to your `go.mod` (or vendor the module and build the shim inside `vendor/`), then compile with `-tags oxc`.

```go
import "github.com/tracewayapp/traceway/backend/v2/app/symbolicator/sourcemap/scopes"

if err := scopes.SetParser("oxc"); err != nil {
	// not compiled in; still on goja
}
```

`scopes.AvailableParsers()` lists what your binary was built with. The parser affects resolver build speed only, never output, so `.tw` files are interchangeable between the two.
